# MangoWM Module

This module owns the MangoWM compositor config, the Mango-specific
`systemd --user` session graph, and the generated monitor/tag/workspace assets
that sit on top of the shared monitor and workspace manifests.

Like the Niri and Hyprland modules, MangoWM is UWSM-first and treats generated
files as build artifacts rather than hand-edited sources.

## Operational Model

- `modules/sessions/dotfiles/mango-uwsm.desktop` is the single display-manager
  session entry for MangoWM.
- `modules/sessions/dotfiles/mango-uwsm-session` loads the curated Mango
  environment stack through `mango-session-common`, applies the session
  identity (`DESKTOP_SESSION=mango-uwsm`, `XDG_CURRENT_DESKTOP=mango`), and
  then enters `uwsm start -- mango-session`.
- The repo-managed drop-in at
  `dotfiles/systemd/user/wayland-wm@mango\x2dsession.service.d/10-session-lifecycle.conf`
  starts `mangowm-session.target` with `ExecStartPost=` once the compositor is
  actually running.
- `scripts/install.sh` is the post-install hook. It renders the Mango theme,
  profile, and workspace assets, runs validation, and reloads the user systemd
  manager.

This module does not own the display-manager session entry installation logic
itself. That belongs to the `sessions` module.

## Source Of Truth

- Monitor geometry and profile-to-monitor mappings live in
  [shared/wm/monitors.yaml](../../shared/wm/monitors.yaml).
- The selected Mango monitor profile lives in
  [profiles/profile.env](./profiles/profile.env) via `MANGO_MONITOR_PROFILE`.
- Workspace routing, `here` metadata, focus matching, and launch metadata live
  in [modules/niri/workspaces/workspaces.json](../niri/workspaces/workspaces.json).
- Mango visual defaults live in [theme/theme.env](./theme/theme.env).

The important consequence is:

- `shared/wm/monitors.yaml` owns static monitor placement and profile layouts.
- `modules/niri/workspaces/workspaces.json` owns app-to-workspace semantics for
  Mango too; Mango does not maintain a separate workspace manifest.
- `theme/theme.env` owns Mango-generated theme output.
- Files under `dotfiles/mango/generated/` are render outputs, not canonical
  inputs.

## Generated Assets

### Static Repo Outputs

- [dotfiles/mango/generated/theme.conf](./dotfiles/mango/generated/theme.conf)
  Generated by `scripts/render-theme.sh` from `theme/theme.env`.
- [dotfiles/mango/generated/profile.conf](./dotfiles/mango/generated/profile.conf)
  Generated by `scripts/render-profile.sh` from
  `shared/wm/monitors.yaml + profiles/profile.env + workspaces.json`.
- [dotfiles/mango/generated/workspace-binds.conf](./dotfiles/mango/generated/workspace-binds.conf)
  Generated by `scripts/render-profile.sh` from the same monitor/workspace
  inputs.
- [dotfiles/mango/generated/workspace-rules.conf](./dotfiles/mango/generated/workspace-rules.conf)
  Generated by `scripts/render-workspace-assets.sh` from
  `workspaces.json + shared/wm/monitors.yaml + profiles/profile.env`.

### Managed Session Assets

- [dotfiles/environment.d/10-mangowm.conf](./dotfiles/environment.d/10-mangowm.conf)
  Installed to `~/.config/session-env/mangowm/10-mangowm.conf` as the Mango
  session overlay.
- [dotfiles/environment.d/mangowm-session.envlist](./dotfiles/environment.d/mangowm-session.envlist)
  Installed to `~/.config/environment.d/mangowm-session.envlist` as the
  ordered allowlist manifest consumed by the Mango UWSM wrapper.
- [dotfiles/portals.conf](./dotfiles/portals.conf)
  Installed to `~/.config/xdg-desktop-portal/mango-portals.conf` as the Mango
  portal preference file.

## Config Layout

- [dotfiles/mango/config.conf](./dotfiles/mango/config.conf)
  Minimal root config. It sources static config first, then the generated
  theme/profile/workspace files, then the hand-maintained rules/binds/gesture
  layers.
- [dotfiles/mango/conf.d/20-layout.conf](./dotfiles/mango/conf.d/20-layout.conf)
  Owns the global scroller-biased layout policy, including width presets and
  centering behavior.
- [dotfiles/mango/conf.d/30-window-rules.conf](./dotfiles/mango/conf.d/30-window-rules.conf)
  Owns the hand-maintained app/window exceptions that are not generated from
  the shared workspace manifest.
- [dotfiles/mango/conf.d/50-binds.conf](./dotfiles/mango/conf.d/50-binds.conf)
  Owns the core Mango keybind layer, including layout binds, shell/session
  actions, media helpers, and `Super+Shift+1..9` moves via `mango-tag-smart`.
- [dotfiles/mango/conf.d/60-gestures.conf](./dotfiles/mango/conf.d/60-gestures.conf)
  Owns Mango gesture policy separately from keybinds.
- [dotfiles/mango/conf.d/70-autostart.conf](./dotfiles/mango/conf.d/70-autostart.conf)
  Keeps compositor-native autostart isolated from the user-service session
  graph.

## Workspace Semantics

`modules/niri/workspaces/workspaces.json` is the canonical workspace manifest
for Mango too. Mango consumes it in two different ways:

- generated routing rules in `generated/workspace-rules.conf`
- generated profile-aware workspace binds in `generated/workspace-binds.conf`

That manifest can describe:

- `here.target`
- `focus.regex`
- `routes[]`
- `launch.commands`
- optional `tagSilent`

The important Mango helpers are:

- `mango-workspace-smart`
  Used by `Super+1..9`. It switches to the requested tag on the monitor that
  owns that tag in the active profile.
- `mango-tag-smart`
  Used by `Super+Shift+1..9`. It moves the focused client to the requested tag
  while staying profile-aware. These binds intentionally use physical
  number-row keycodes in `50-binds.conf` so they survive non-US keyboard
  layouts.
- `mango-here`
  Used by `Alt+1..9`. It mirrors the Niri-style “app recall” behavior:
  focus the mapped app if it is already on the current tag, move it to the
  current tag if it is open elsewhere, or launch it if it is not open yet.

## Session Graph

Core session units:

- `mangowm-session.target`
  Mango session umbrella target started by the compositor lifecycle drop-in.
- `mango-session-env.service`
  Early runtime env sync. Runs `mango-session-init --no-start-target` so the
  user manager sees the finalized Mango runtime variables before the rest of
  the graph starts.
- `mango-bootstrap.service`
  Early oneshot bootstrap stage.
- `mango-audio-init.service`
  Separate audio initialization stage.
- `mango-shell-ensure.service`
  Shell-backend ensure stage before tray readiness is checked.
- `mango-daemons.target`
  Explicit daemon stage for the long-running Mango session helpers.
- `mango-post-daemons.target`
  Ordered late-stage target for post-daemon oneshots.
- `mango-desktop-settings.service`
  Tracked desktop theme/settings sync.
- `mango-post-bootstrap.service`
  Final late-stage Mango polish.
- `mango-status-notifier-ready.service`
  Readiness gate for tray-dependent applets.

Daemon-stage services:

- `mango-polkit-agent.service`
- `mango-nm-applet.service`
- `mango-blueman-applet.service`

## Validation

- `scripts/install.sh` renders the generated files, runs validation, and then
  reloads the user manager.
- `scripts/validate.sh` runs:
  - `render-theme.sh --check`
  - `render-profile.sh --check`
  - `render-workspace-assets.sh --check`
  - `jq empty modules/niri/workspaces/workspaces.json`
  - `bash -n` across the Mango helper/session scripts
  - `mango -c modules/mangowm/dotfiles/mango/config.conf -p`

Run it directly with:

```bash
modules/mangowm/scripts/validate.sh
```

## Notes

- `generated/profile.conf`, `generated/workspace-binds.conf`, and
  `generated/workspace-rules.conf` should be regenerated, not edited by hand.
- `generated/theme.conf` is derived strictly from `theme/theme.env`.
- Mango workspace ownership is profile-driven; changing monitor placement means
  updating `shared/wm/monitors.yaml` and/or `profiles/profile.env`, not editing
  `profile.conf` directly.
- Mango app/workspace behavior is intentionally aligned with the shared
  workspace manifest so Niri and Mango do not drift apart on app recall and
  routing rules.
