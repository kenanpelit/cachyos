# MangoWM Module

This module owns the MangoWM compositor config, the Mango-specific
`systemd --user` session graph, and the generated config assets layered on top
of the shared monitor/workspace manifests.

For the full UWSM and lifecycle graph, see
[docs/session-graph.md](./docs/session-graph.md).

## Operational Model

- `modules/sessions/dotfiles/mango-uwsm.desktop` is the single display-manager
  session entry for MangoWM.
- `modules/sessions/dotfiles/mango-uwsm-session` loads the curated Mango
  environment stack through `mango-session-common`, applies the session
  identity (`DESKTOP_SESSION=mango-uwsm`, `XDG_CURRENT_DESKTOP=mango`), and
  then enters `uwsm start -- mango-session`.
- The repo-managed drop-in at
  `dotfiles/systemd/user/wayland-wm@mango\x2dsession.service.d/10-session-lifecycle.conf`
  starts `mangowm-session.target` with `ExecStartPost=` once the compositor is
  actually running.
- `scripts/install.sh` is the canonical post-install hook. It renders the
  generated assets, refreshes the runtime compatibility links, reloads user
  units, and applies the Mango session migrations.
- `scripts/ensure-runtime-files.sh` is the lower-level render/link helper that
  keeps the runtime mirror aligned with the generated repo outputs.

## Source Of Truth

- Monitor geometry and profile-to-monitor mappings live in
  [shared/wm/monitors.yaml](../../shared/wm/monitors.yaml).
- Shared workspace routing, `here` metadata, focus matching, and launch
  metadata live in [shared/wm/workspaces.json](../../shared/wm/workspaces.json).
- The selected Mango monitor profile lives in
  [profiles/profile.env](./profiles/profile.env) via `MANGO_MONITOR_PROFILE`.
- Mango visual defaults live in [theme/theme.env](./theme/theme.env).
- Generated Mango window/app rules live in
  [rules/window-rules.json](./rules/window-rules.json).

The important consequence is:

- `shared/wm/monitors.yaml` owns static monitor placement and profile layouts.
- `shared/wm/workspaces.json` owns app-to-workspace semantics for both Mango
  and Niri.
- `theme/theme.env` owns the generated Mango theme and package outputs.
- `rules/window-rules.json` owns the canonical generated `windowrule=`
  surface.
- Files under `dotfiles/mango/generated/` are canonical derived outputs.
- Files under `~/.config/mango/runtime/` are a compatibility symlink mirror for
  helpers and plugins that still read the historical runtime paths.

## Config Layout

- [dotfiles/mango/config.conf](./dotfiles/mango/config.conf)
  Minimal root config. It sources static config first, then the generated
  theme/profile/workspace assets, then the
  hand-maintained rules/binds/gesture layers.
- [dotfiles/mango/conf.d/20-layout.conf](./dotfiles/mango/conf.d/20-layout.conf)
  Owns the global scroller-biased layout policy, including width presets and
  centering behavior.
- [dotfiles/mango/conf.d/25-virtual-output.conf](./dotfiles/mango/conf.d/25-virtual-output.conf)
  Pre-registers the `HEADLESS-*` output family used by Mango virtual outputs
  so remote-desktop and capture sessions get predictable geometry.
- [dotfiles/mango/conf.d/30-window-rules.conf](./dotfiles/mango/conf.d/30-window-rules.conf)
  Is reserved for local/manual overrides. Canonical shared app/window rules are
  generated from `rules/window-rules.json` into
  `generated/window-rules.conf`.
- [dotfiles/mango/conf.d/40-layer-rules.conf](./dotfiles/mango/conf.d/40-layer-rules.conf)
  Owns the layer-shell rules directly in one file for capture, launcher,
  shell-surface, and notification-specific behavior. Notification/OSD layers
  intentionally disable blur, shadow, and animation so volume/brightness
  feedback stays crisp.
- [dotfiles/mango/conf.d/50-binds.conf](./dotfiles/mango/conf.d/50-binds.conf)
  Owns the core Mango keybind layer. It is now explicitly split into
  `keymode=common`, `keymode=default`, `keymode=layout`, and
  `keymode=monitor` sections so advanced layout/monitor controls do not need
  to live only in global chords. Long-lived app launches prefer `uwsm app`.

## Mango-Specific Improvements

- `MANGO_MONITOR_PROFILE=auto` selects the best profile from live `mmsg -O`
  output, then `wlr-randr`, then falls back to `desk` for offline renders.
- `rules/window-rules.json` keeps the high-volume rule surface reviewable:
  scroller proportions, portal/dialog floating rules, named scratchpads,
  terminal swallowing, PiP/media placement, password-manager sharpness, and
  low-latency game/remote-play rules.
- `mango-overview` wraps `toggleoverview` with idempotent `open`, `close`,
  `toggle`, and `status` actions. Four-finger up opens overview and
  four-finger down closes it without getting stuck in the blurred overview
  state.
- `mango-layer-audit` watches layer-shell names so launcher, shell, OSD, and
  notification rules can be tuned from live IPC instead of guesswork.
- `mango-virtual-output` creates or destroys a headless output for remote
  desktop and screen-share workflows, then configures it through `wlr-randr`.
- `mango-profile-select` reports the monitor profile that best matches the
  connected outputs and can write the selected profile back with `--write`.
- `mango-performance-mode` applies runtime Mango profiles for normal, gaming,
  and battery use through the native `setoption` dispatcher.
- `mango-state-bridge` exports live Mango IPC state as JSON under
  `~/.cache/mango/state.json` for shell widgets and future Noctalia plugins.
- Layout bindings now expose scroller stack movement and Mango's `zoom`
  dispatcher in both default and layout keymodes. The dedicated layout mode
  also exposes smart floating move/resize, gap adjustment, border toggling,
  center-window, all-floating toggle, and focus-last controls.
- Monitor mode exposes profile detection, virtual-output control, trackpad
  toggling, panel-output power toggling, and spawn-on-empty testing without
  polluting the default mode.
- `SUPER+ALT+f`, `SUPER+ALT+v`, `SUPER+ALT+a`, and
  `SUPER+CTRL+ALT+d` open named Yazi, Clipse, Wiremix, and Mango doctor
  scratchpads instead of one-off terminal spawns.

## Workspace Semantics

`shared/wm/workspaces.json` is the canonical workspace manifest for Mango too.
Mango consumes it in three different ways:

- generated routing rules in `generated/workspace-rules.conf`
- generated profile-aware workspace binds in `generated/workspace-binds.conf`
- generated cheatsheet metadata in `generated/keybind-cheatsheet.conf`

That manifest can describe:

- `here.target`
- `focus.regex`
- `routes[]`
- `launch.commands`
- optional `tagSilent`
- optional `layout.lines` for the shared Niri-facing layout hints
- optional `layout.mango.layoutName`
- optional `layout.mango.mfact`
- optional `layout.mango.nmaster`
- optional `layout.mango.noHide`
- optional `layout.mango.openAsFloating`
- optional `layout.mango.noRenderBorder`

The important Mango helpers are:

- `mango-workspace-smart`
  Used by `Super+1..9`. It switches to the requested tag on the monitor that
  owns that tag in the active profile.
- `mango-tag-smart`
  Used by `Super+Shift+1..9`. It moves the focused client to the requested tag
  while staying profile-aware.
- `mango-here`
  Used by `Alt+1..9` and `Alt+0`. It focuses the mapped app if it is already on
  the current tag, moves it here if it is open elsewhere, or launches it. The
  `all` mode gathers every workspace target marked `includeInAll`, then ends on
  Kenp.
- `mango-arrange go`
  Used by `Super+Alt+0`. It applies the generated workspace routing rules to
  open windows so drifted apps return to their profile-aware tag and monitor.

## Session Graph

Core session units:

- `mangowm-session.target`
  Mango session umbrella target started by the compositor lifecycle drop-in.
- `mango-session-env.service`
  Early runtime env sync.
- `mango-bootstrap.service`
  Early oneshot bootstrap stage.
- `mango-arrange.service`
  Profile-aware tag arrangement stage that reconciles monitor/tag ownership
  from `generated/profile.conf` via the runtime compatibility mirror.
- `mango-daemons.target`
  Explicit daemon stage for long-running Mango session helpers.
- `mango-state-bridge.service`
  Long-running IPC-to-JSON bridge for shell/session integrations.
- `mango-post-daemons.target`
  Ordered late-stage target for post-daemon oneshots.
- `mango-session-ready.target`
  Ready-stage target that waits for arrange, settings sync, and late bootstrap
  polish.

## Validation

- `scripts/validate.sh` defaults to a Mango-focused `--fast` mode.
- `scripts/validate.sh --strict` additionally syntax-checks every helper under
  `modules/scripts/bin`.
- `scripts/validate.sh --live` adds active Mango IPC/session checks on top of
  the generated config validation.
- Validation includes:
  - shared monitor asset drift
  - shared workspace manifest syntax and semantic validation
  - package/theme/generated asset drift
  - package-variant backend sanity via `pacman` when available
  - runtime compatibility mirror checks
  - duplicate keybind detection with keymode awareness
  - rendered Mango `tagrule=` contract checks against `layout.mango`
  - generated window-rule manifest validation
  - opt-in generated window-rule key drift against a local Mango source tree
    when `MANGO_VALIDATE_SOURCE=1` is set
  - temporary generated/runtime render + `mango -p` parse validation
  - live output/tag/keymode, layer-rule coverage, systemd unit verification,
    and failed Mango user-unit checks in `--live` mode

Run it directly with:

```bash
modules/mangowm/scripts/validate.sh
modules/mangowm/scripts/validate.sh --live
```

## Notes

- `packages.yaml`, `generated/profile.conf`, `generated/workspace-binds.conf`,
  `generated/workspace-rules.conf`, `generated/window-rules.conf`, and
  `generated/keybind-cheatsheet.conf` should be regenerated, not edited by hand.
- `runtime/profile.conf`, `runtime/workspace-binds.conf`,
  `runtime/workspace-rules.conf`, `runtime/window-rules.conf`, and
  `runtime/keybind-cheatsheet.conf` are compatibility symlinks and should stay
  disposable.
- Mango monitor ownership is profile-driven; changing monitor placement means
  updating `shared/wm/monitors.yaml` and/or `profiles/profile.env`.
- Mango app/workspace behavior is intentionally aligned with the shared
  workspace manifest so Mango and Niri do not drift apart on app recall and
  routing rules.
