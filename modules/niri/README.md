# Niri Module

This module owns the Niri compositor config, the Niri-specific
`systemd --user` session graph, and the generated workspace/runtime assets that
sit on top of the shared monitor manifest.

For the full UWSM/session graph design, see
[docs/session-graph.md](./docs/session-graph.md).

## Operational Model

- `modules/sessions/dotfiles/niri-uwsm.desktop` is the single session entry.
- `modules/sessions/dotfiles/niri-uwsm-session` loads the curated environment
  stack, applies the Niri session identity, and runs `uwsm start -- niri-session`.
- `modules/niri/dotfiles/systemd/user/niri-session.target` is the Niri session
  umbrella target.
- `modules/niri/scripts/ensure-runtime-files.sh` regenerates repo/runtime assets
  and keeps `~/.config/niri/{config.kdl,outputs.kdl,conf,generated}` pointed at
  the repo copies.

## Source Of Truth

- Monitor and workspace placement profile data lives in
  [shared/wm/monitors.yaml](../../shared/wm/monitors.yaml).
- The active Niri profile selector lives in
  [profiles/profile.env](./profiles/profile.env) via `NIRI_MONITOR_PROFILE`.
- Workspace routing, `here` metadata, and launch metadata live in
  [shared/wm/workspaces.json](../../shared/wm/workspaces.json).

The important consequence is:

- `shared/wm/monitors.yaml` owns static outputs and profile-to-monitor mappings.
- `shared/wm/workspaces.json` owns app/workspace semantics.
- Repo-generated files under `dotfiles/niri/generated/` and
  `~/.config/niri/runtime/` are build artifacts, not hand-edited sources.

## Generated Assets

### Static Repo Outputs

- [dotfiles/niri/outputs.kdl](./dotfiles/niri/outputs.kdl)
  Generated from `shared/wm/monitors.yaml`.
- [dotfiles/niri/generated/workspace-shortcuts.kdl](./dotfiles/niri/generated/workspace-shortcuts.kdl)
  Generated from `shared/wm/workspaces.json`.
- [dotfiles/niri/generated/workspace-rules.kdl](./dotfiles/niri/generated/workspace-rules.kdl)
  Generated from `shared/wm/workspaces.json`.

### Runtime Outputs

- `~/.config/niri/runtime/workspaces-auto.kdl`
  Generated by `scripts/render-profile.sh` from
  `shared/wm/monitors.yaml + profiles/profile.env + shared/wm/workspaces.json`.
- `~/.config/niri/runtime/workspace-rules.tsv`
  Generated by `scripts/render-workspace-assets.sh`.
- `~/.config/niri/runtime/workspace-here.tsv`
  Generated by `scripts/render-workspace-assets.sh`.

### Shared Consumers

- Noctalia workspace metadata is now rendered by the Noctalia module from the
  same `shared/wm/workspaces.json` source. Niri no longer writes into the
  Noctalia module tree directly.

## Layout Ownership

- Global layout behavior such as gaps, centering, borders, and window-height
  presets lives in [dotfiles/niri/conf/10-layout.kdl](./dotfiles/niri/conf/10-layout.kdl).
- Output-specific default column width and column width presets live in
  [shared/wm/monitors.yaml](../../shared/wm/monitors.yaml) and are rendered into
  [dotfiles/niri/outputs.kdl](./dotfiles/niri/outputs.kdl).

This removes duplicate width presets between the global layout file and the
generated output file.

## Workspace Metadata

`shared/wm/workspaces.json` is now the canonical workspace manifest. Each
workspace can describe:

- `here.label` and `here.target`
- `focus.regex`
- `routes[]`
- optional `layout.lines`
- optional `launch.commands`
- optional `launch.includeInAll`

That manifest feeds:

- Native Niri `window-rule` generation
- Runtime TSV files consumed by `niri-osc`
- Shared launch-resolution helpers such as `osc-workspace-launch`
- Noctalia workspace metadata

## Validation

- `scripts/validate.sh` defaults to a Niri-focused `--fast` mode.
- `scripts/validate.sh --strict` additionally syntax-checks every helper under
  `modules/scripts/bin`.

The default fast path is intentional: unrelated helper drift elsewhere in the
repo should not block normal Niri validation.

## Notes

- Native Niri recent-window switching is bound on `Mod+Tab` and related chords.
- `niri-osc` remains the main session/workspace helper multiplexer.
- Shared launch commands are now resolved through `osc-workspace-launch`, so
  launch metadata is no longer duplicated across Niri/Hyprland/Mango helpers.
